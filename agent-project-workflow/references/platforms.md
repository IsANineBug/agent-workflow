# references/platforms.md — 平台说明

> **我是以下事实的唯一来源**：各平台的 skill 安装路径、**能力降级行为**。
> `SKILL.md` 提到平台差异或工具缺失时只能给指针，不得复述本文件内容。

**核心原则：只写验证过的。**

没验证过的适配方案等于猜 —— 猜出来的适配比留空更危险，因为下一个 agent 会信任它。

## 0. 能力降级总表

**「没有这个工具」和「工具有、但当前上下文不让用」是两回事。** 后者例如子会话、批处理模式。

| 能力 | 有 | 没有 | 存在但被禁用 |
|---|---|---|---|
| 带选项的提问工具 | 用工具给选项 | 纯文本编号选项，效果等价 | 见 §0.1 |
| 可写的 skill 目录 | 正常记录观察 | 退回用户主目录；都不可写则**静默跳过** | 同「没有」 |
| `wc` / `grep` 等命令 | 用命令实测 | 用自身能力估算，并说明估算方式 | 同「没有」 |
| `context-efficient-docs` skill | 调用它做文档体检 | 跳过，只做最小自检（行数估算） | 同「没有」 |
| 子 agent / 并行执行 | 可用于 evals | evals 改为串行执行 | 同「没有」 |

### 0.1 工具被禁用时

实测遇到的例子：子 agent 调用交互提问工具，返回
`human interaction is unavailable while the calling agent is owned by another live agent`。

**处理方式**：

1. **把问题原样交回调用方**（父 agent / 上层），**绝不自己编答案**
2. 若调用方也可能失联 → **把问题落盘成一份文件**，并在 `docs/KICKOFF-STATUS.md` 里**只放指针**（不要两处都写全文）
3. 在最终回复里说明这个限制，让用户知道问题为什么是「转达」而不是「直接问」的

> 落盘的问题清单文件**不在 §8 的产出物清单里** —— 它是**降级产物**，只在通道不可用时才出现。用得到就建，用不到别建。

## 2. 其他平台 — ⬜ 未验证

**目前没有第二个验证过的平台。** 这一节保持为空是有意的，不是遗漏。

新增平台时，复制下面的模板填写：

```markdown
### {{平台名}} — ⬜ 未验证

| 项 | 值 |
|---|---|
| skill 目录 | |
| 安装路径 | |
| 验证时间 | |
| 验证方式 | |

| 能力 | 状态 | 实际行为 |
|---|---|---|
| 带选项的提问工具 | | |
| 可写的 skill 目录 | | |
| `wc` / `grep` | | |
| `context-efficient-docs` skill | | |
| 子 agent / 并行执行 | | |
```

### 填写要求

1. **每一项都必须实际跑过才能填。** 没跑过的留空，并保持「⬜ 未验证」标记。
2. **不要抄其他平台的文档。** 官方文档写的是设计意图，不是这个 skill 的实测行为。
3. 平台名旁的标记只有两种：`✅ 已验证` / `⬜ 未验证`。不要发明第三种（比如「应该可以」）。
4. 验证方式要写成**别人能重跑**的动作，不要写「测试通过」。
